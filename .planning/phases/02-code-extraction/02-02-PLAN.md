<objective>
Extract URL parsing and attachment hashing from Ribbon.cs into dedicated UrlExtractor and AttachmentHasher classes, fixing the Contains("a") URL bug and temp file leak bug during extraction, and add COM object cleanup across all Ribbon.cs processing methods.

Purpose: This is the core code extraction that transforms Ribbon.cs from a monolith into a thin coordinator. UrlExtractor fixes BUGF-01 (all URLs captured regardless of content). AttachmentHasher fixes BUGF-05 (temp files guaranteed deleted in finally block). COM cleanup (QUAL-05) prevents RCW leaks that cause Outlook sluggishness and shutdown hangs. These three changes must ship together because they all modify GetURLsAndAttachmentsInfo and its callers.

Output: Two new single-responsibility classes (UrlExtractor.cs, AttachmentHasher.cs), a slimmed-down Ribbon.cs with COM cleanup, and updated .csproj.
</objective>

Create `PhishingReporter/UrlExtractor.cs` implementing the URL extraction logic currently inline in Ribbon.cs `GetURLsAndAttachmentsInfo` (lines 261-308), with the BUGF-01 fix (remove `Contains("a")` filter).

**File structure:**
1. Namespace: `PhishingReporter`
2. Define `UrlExtractionResult` sealed class with:
   - `IReadOnlyList<string> Urls` property (get-only)
   - `IReadOnlyList<string> UniqueDomains` property (get-only)
   - Constructor accepting both lists
3. Define `UrlExtractor` static class with:
   - Private static Logger field using `AppLogger.Instance.GetCurrentClassLogger()`
   - Public static `ExtractUrls(string emailHtmlBody)` returning `UrlExtractionResult`

**ExtractUrls implementation:**
1. Guard: if `string.IsNullOrEmpty(emailHtmlBody)`, return empty result using `Array.Empty<string>()`
2. Parse HTML with `new HtmlDocument()` / `doc.LoadHtml(emailHtmlBody)`
3. Select nodes with `doc.DocumentNode.SelectNodes("//a[@href]")`
4. If null, return empty result
5. Iterate over nodes. For each: get `href` attribute value via `link.GetAttributeValue("href", "")`
6. **BUGF-01 FIX:** Do NOT apply any `Contains("a")` filter. Add ALL non-empty href values to the URL list.
7. Domain extraction: try `new Uri(href).Host`. On `UriFormatException`, check for `@` (mailto links) -- extract domain from email address portion. If still unparseable, log a warning via Logger.Warn.
8. Use `HashSet<string>(StringComparer.OrdinalIgnoreCase)` for domain deduplication (replaces the `.Distinct().ToList()` in original).
9. Log extracted count: `Logger.Info("Extracted {0} URLs and {1} unique domains from email body", ...)`
10. Return `new UrlExtractionResult(urls.AsReadOnly(), domains.ToList().AsReadOnly())`

**Required usings:** System, System.Collections.Generic, System.Linq, HtmlAgilityPack

**Follow research pattern exactly** from 02-RESEARCH.md Pattern 2 (UrlExtractor Class). The complete implementation is provided there.

**Anti-pattern to avoid:** Do NOT accept a MailItem parameter. Accept `string emailHtmlBody` only. The caller (Ribbon.cs) passes `mailItem.HTMLBody`. This keeps UrlExtractor pure and free of Outlook OOM dependency.

1. Generate temp path: `Path.Combine(Path.GetTempPath(), "Outlook-Phishaddin-" + Guid.NewGuid().ToString("N") + ".tmp")` -- uses GUID instead of DisplayName to avoid path-illegal characters and collisions

**ComputeMd5 implementation:**
- Use `using (var md5 = MD5.Create())` and `using (var stream = File.OpenRead(filePath))`

- This matches the existing CalculateMD5 pattern in Ribbon.cs

**ComputeSha256 implementation:**
- Use `using (var sha256 = SHA256.Create())` -- NOT `new SHA256Managed()` (obsolete)
- Use `using (var stream = File.OpenRead(filePath))`
- Return `BitConverter.ToString(hash).Replace("-", "").ToLowerInvariant()`
- This replaces the manual byte-to-hex loop in the existing GetHashSha256

**Required usings:** System, System.IO, System.Security.Cryptography, Microsoft.Office.Interop.Outlook

**Follow research pattern exactly** from 02-RESEARCH.md Pattern 3 (AttachmentHasher Class). The complete implementation is provided there.

**Part A: Refactor GetURLsAndAttachmentsInfo (QUAL-03, QUAL-04)**

Replace the entire body of `GetURLsAndAttachmentsInfo(MailItem mailItem)` with delegation to the extracted classes:

1. URL section: call `UrlExtractor.ExtractUrls(mailItem.HTMLBody)` to get `UrlExtractionResult`. Build the domain output string from `result.UniqueDomains` and the URL output string from `result.Urls`, using the same `Replace(":", "[:]")` defanging as current code.

2. Attachment section: iterate `mailItem.Attachments`, call `AttachmentHasher.ComputeHashes(a)` for each, build the hash output string from `AttachmentHashResult` properties. Release each Attachment COM object in a finally block after processing (see Part B).

3. Remove the old inline helper methods from Ribbon.cs:
   - Delete `CalculateMD5(string filename)` (lines 399-409) -- now in AttachmentHasher
   - Delete `GetHashSha256(string filename)` (lines 410-420) -- now in AttachmentHasher
   - The URL parsing code inside GetURLsAndAttachmentsInfo is replaced by the UrlExtractor call

**Part B: COM Object Cleanup (QUAL-05)**

Add `using System.Runtime.InteropServices;` to Ribbon.cs if not already present.

Add Marshal.ReleaseComObject cleanup in the following methods:

1. **reportPhishingEmailToSecurityTeam:** Declare `Selection selection = null;`, `MailItem mailItem = null;`, `MailItem reportEmail = null;` as local variables at the top. Assign them in the try block (they are already declared inline). Add a finally block that releases in reverse order: reportEmail, mailItem, selection. Set each to null after release. The existing try/catch remains inside this outer try/finally.

2. **GetCurrentUserInfos:** Declare `Outlook.NameSpace session = null;`, `Outlook.Recipient currentUserRecipient = null;`, `Outlook.AddressEntry addrEntry = null;`, `Outlook.ExchangeUser currentUser = null;`. Store each intermediate COM object in a named local (no property chaining). Add finally block releasing in reverse order: currentUser, addrEntry, currentUserRecipient, session. This fixes the existing pattern where `Globals.ThisAddIn.Application.Session.CurrentUser.AddressEntry.GetExchangeUser()` chains multiple COM accesses without releasing intermediates.

3. **GetBasicInfo:** Declare `Outlook.MAPIFolder parentFolder = null;`. Assign in try. Release in finally.

4. **GetURLsAndAttachmentsInfo (attachment loop):** After the foreach loop, release individual attachment COM objects. Use a for loop with index instead of foreach to get a reference. After each `AttachmentHasher.ComputeHashes(a)` call, release the attachment in a try/finally.

**COM cleanup rules (from research):**
- Release in REVERSE order of acquisition
- Set variable to null after release
- Wrap each ReleaseComObject in its own try/catch -- never let ReleaseComObject exceptions propagate
- Do NOT release `Globals.ThisAddIn.Application` or `ActiveExplorer()` -- they are long-lived VSTO objects
- Use `Marshal.ReleaseComObject` (single decrement), NOT `Marshal.FinalReleaseComObject`
